# Visitrip

Open-source app for organizing, sharing, and real-time collaborating on trips with friends.

> **Status:** early but usable end-to-end. You can sign up, create a trip, and load it back from Postgres. Most write paths beyond create-trip (day items, expenses, packing, docs, invite acceptance) and real-time editing are still to come.

## What works today

- Email + password auth via better-auth (sign-up, sign-in, sign-out, session)
- Create / list / open trips; full trip settings sheet (edit title, dates, cover, summary; archive; owner-only delete)
- Itinerary: add / delete days, add / delete day items, drag-reorder with server-persisted positions
- Expenses: add / delete; budget summary
- Packing list: **real-time collaborative** — add, toggle, remove broadcast to every connected client via Yjs over WebSocket, with debounced persistence to Postgres
- Live presence: a green dot on the member avatar stack when other members are connected to the same trip
- Invite link: per-trip share URL (`/invite/<token>`) with role choice (editor / viewer); preview screen for recipients; one-click accept after sign-in
- Profile screen tied to the real session user; sign-out
- Six trip-cover options
- Installable PWA shell (manifest + service worker generated by `vite-plugin-pwa`)
- Self-host via a single `docker compose up --build`

## Planned

- Migrate days / day items / expenses onto the same Yjs doc so non-packing edits go live too (packing is the reference panel)
- Object storage for document uploads (currently a no-op button)
- Email delivery for invites and the forgot-password flow (the reset screen is a placeholder)
- Persistent profile preferences (currency / week-start / notifications)
- Offline support for already-loaded trips
- CI, tests, linting config

## Quickstart (local dev)

Requirements: Node `>=20`, npm, Docker (or a locally-installed Postgres 16+).

```bash
# 1. install workspace dependencies
npm install

# 2. copy env defaults and set a real BETTER_AUTH_SECRET
cp .env.example .env
# edit .env — at minimum, run:  openssl rand -base64 32
# and paste the result as BETTER_AUTH_SECRET

# 3. start postgres (or point DATABASE_URL at your own)
docker compose up -d postgres

# 4. apply migrations
npm run db:migrate

# 5. run web + api together
npm run dev
```

Then:

- Web: <http://localhost:5173>
- API: <http://localhost:3001/health>

The Vite dev server proxies `/api/*` to the API, so the frontend can call the backend without CORS in development.

To run only one side:

```bash
npm run dev:web   # vite dev server
npm run dev:api   # tsx watch on the Hono server (requires postgres + migrations)
```

## Database

Drizzle schema lives in `packages/db/src/schema.ts`. Migrations are tracked under `packages/db/migrations/`.

```bash
npm run db:generate   # emit a new SQL migration from a schema diff
npm run db:migrate    # apply pending migrations
npm run db:studio     # open Drizzle Studio
```

Tables: `user`, `session`, `account`, `verification` (better-auth) plus `trip`, `trip_member`, `day`, `day_item`, `expense`, `packing_item`, `trip_doc`.

## Self-hosting with Docker

```bash
cp .env.example .env
# edit .env — at minimum, set BETTER_AUTH_SECRET (32+ random bytes)
docker compose up --build -d
# Migrations run automatically on api boot.
# To opt out, set AUTO_MIGRATE=false in .env and run them yourself.
```

Stack:

- `postgres` — Postgres 17 with a named volume for data
- `api`     — Hono server, exposed on `:3001`
- `web`     — built static bundle served by nginx on `:5173`; nginx proxies `/api/*` to the api service so the session cookie stays same-origin
