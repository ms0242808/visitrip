# Visitrip

Open-source app for organizing, sharing, and real-time collaborating on trips with friends.

> **Status:** early but usable end-to-end. You can sign up, create a trip, and load it back from Postgres. Most write paths beyond create-trip (day items, expenses, packing, docs, invite acceptance) and real-time editing are still to come.

## What works today

- Email + password auth via better-auth (sign-up, sign-in, sign-out, session)
- Create / list / open trips; full trip settings sheet (edit title, dates, cover, summary; archive; owner-only delete)
- Itinerary: add / delete days, add / delete day items, drag-reorder with server-persisted positions
- Expenses: add / delete; budget summary
- Packing list: **real-time collaborative** — add, toggle, remove broadcast to every connected client via Yjs over WebSocket, with debounced persistence to Postgres
- Live presence: a green dot on the member avatar stack when other members are connected to the same trip
- Invite link: per-trip share URL (`/invite/<token>`) with role choice (editor / viewer); preview screen for recipients; one-click accept after sign-in
- Profile screen tied to the real session user; sign-out
- Six trip-cover options
- Installable PWA shell (manifest + service worker generated by `vite-plugin-pwa`)
- Self-host via a single `docker compose up --build`

## Known issues

### Critical

- **y-websocket cross-tab packing leak** — `apps/web/src/lib/yjs.tsx:46` passes `""` as the y-websocket roomname, so the `BroadcastChannel` name is identical for every trip. Two tabs on different trips will cross-pollinate packing items via BC and then persist the corrupted state via WS. Pass `tripId` as the roomname.
- **`engines.node: ">=20"` is too loose** — `--env-file` (used in `apps/api/package.json:8`) requires Node ≥20.6, and `process.loadEnvFile` (used in `packages/db/drizzle.config.ts:3`) requires Node ≥20.12. Bump `engines.node` in root `package.json` accordingly.

### Important

- **Viewer role isn't enforced on write endpoints** — `apps/api/src/routes/trips.ts:234+` and every mutating trip/day/item/expense/invite route check membership but not role. Members invited as `viewer` can PATCH/DELETE everything, contradicting the read-only promise in `apps/web/src/screens/invite.tsx:117` and the "Invite link" claim above. `requireMembership` already returns `role`; just gate writes on it.
- **Packing data-loss window on api restart** — `apps/api/src/realtime/docs.ts:56-79` debounces persistence by 1s and never mirrors Yjs commits back into `packing_item`. Every restart silently rolls back the last second of packing edits. Persist on first dirty edit (or on each client disconnect) and mirror commits into the table.
- **`useMemo` opens the Yjs WebSocket** — `apps/web/src/lib/yjs.tsx:41`. React 19 can discard memoized values without invoking cleanup, leaking sockets and awareness state on the server. Use `useState(() => …)` or move construction into `useEffect`.
- **`setAcceptMode` called during render** — `apps/web/src/App.tsx:123-125` causes an extra render cycle and a dev-mode warning on every invite sign-in. Move into a `useEffect` watching `state.status` and `pendingInvite`.
- **Invite tokens accumulate forever** — `apps/web/src/screens/invite.tsx:23-43` creates a new row every time the sheet mounts or the role flips. No expiry, no revoke UI; the schema's `revoked` flag is unused. Find-or-create per `(tripId, role)` or add expiry + a revoke endpoint.
- **Membership listing silently capped at 50** — `apps/api/src/routes/trips.ts:116-123` limits the membership query to 50 rows; the 51st member is invisible and locked out. Drop the `.limit`, or split into a 1-row authz check + an unbounded listing query.
- **Day-item reorder doesn't validate permutation** — `apps/api/src/routes/trips.ts:415-423`. Partial or duplicate `ids` arrays corrupt ordering silently. Verify `ids` matches the day's current item set before reassigning positions.

### Minor

- PWA manifest has empty `icons: []` (`apps/web/vite.config.ts:20`); install doesn't actually work in Chrome or Safari. Add 192/512 PNG icons or drop "Installable PWA shell" above.
- `useYArray` has a dead `useMemo`-built `subscribe` factory with a `void subscribe;` line (`apps/web/src/lib/yjs.tsx:81-97`). Finish migrating to `useSyncExternalStore` or delete the dead code.
- Root `dev` script uses Unix-only `&` (`package.json:11`); document that Windows isn't supported or replace with a portable orchestrator.
- No global Hono `app.onError` handler (`apps/api/src/index.ts`); uncaught throws leak stack traces and produce inconsistent JSON shapes vs. the rest of the API.
- `GET /api/trips/:id` runs six queries serially (`apps/api/src/routes/trips.ts:116-166`); parallelize the independent ones with `Promise.all`.
- In-memory `Y.Doc` map never evicts (`apps/api/src/realtime/docs.ts:14`); trip deletion doesn't notify or evict — a stale doc can FK-fail when persisting.
- API docker image ships the full workspace-hoisted `node_modules` (including devDeps like `tsx`/`tsup`/`typescript`/`vite`) because the runtime stage copies `/repo/node_modules` wholesale (`apps/api/Dockerfile:17`). A prod-only install in a third stage would shrink the image substantially.

## Quickstart (local dev)

Requirements: Node `>=20`, npm, Docker (or a locally-installed Postgres 16+).

```bash
# 1. install workspace dependencies
npm install

# 2. copy env defaults and set a real BETTER_AUTH_SECRET
cp .env.example .env
# edit .env — at minimum, run:  openssl rand -base64 32
# and paste the result as BETTER_AUTH_SECRET

# 3. start postgres (or point DATABASE_URL at your own)
docker compose up -d postgres

# 4. apply migrations
npm run db:migrate

# 5. run web + api together
npm run dev
```

Then:

- Web: <http://localhost:5173>
- API: <http://localhost:3001/health>

The Vite dev server proxies `/api/*` to the API, so the frontend can call the backend without CORS in development.

To run only one side:

```bash
npm run dev:web   # vite dev server
npm run dev:api   # tsx watch on the Hono server (requires postgres + migrations)
```

## Database

Drizzle schema lives in `packages/db/src/schema.ts`. Migrations are tracked under `packages/db/migrations/`.

```bash
npm run db:generate   # emit a new SQL migration from a schema diff
npm run db:migrate    # apply pending migrations
npm run db:studio     # open Drizzle Studio
```

Tables: `user`, `session`, `account`, `verification` (better-auth) plus `trip`, `trip_member`, `day`, `day_item`, `expense`, `packing_item`, `trip_doc`.

## Self-hosting with Docker

```bash
cp .env.example .env
# edit .env — at minimum, set BETTER_AUTH_SECRET (32+ random bytes)
docker compose up --build -d
# Migrations run automatically on api boot.
# To opt out, set AUTO_MIGRATE=false in .env and run them yourself.
```

Stack:

- `postgres` — Postgres 17 with a named volume for data
- `api`     — Hono server, exposed on `:3001`
- `web`     — built static bundle served by nginx on `:5173`; nginx proxies `/api/*` to the api service so the session cookie stays same-origin
